# The TwoPunctures oracle

The external code this package validates against, and the recipe that builds it.
`make oracle` runs `build.sh`.

```bash
make oracle                     # -> ~/.cache/lemaitre/tp-oracle/tp_solve
LM_TP_PREFIX=/somewhere ./oracle/build.sh    # or install elsewhere
```

## What is here, and what deliberately is not

| | |
|---|---|
| `build.sh` | generates the C sources, compiles them, installs the binary |
| `gen_tp.py` | emits the TwoPunctures C sources from NRPy (~40 lines of glue) |
| `src/main.c` | **ours** — a thin CLI driver over the solver |
| `src/TP_*.c`, `src/TP_*.h`, `src/BHaH_defines.h` | **not committed** — generated by `gen_tp.py` at build time, and gitignored |

The generated sources are third-party code (NRPy's port of TwoPunctures), so they
are produced on demand rather than vendored here. That keeps this repository free
of code it does not own, and means the build is pinned to whatever `nrpy` version
you install rather than to a stale copy.

## What the oracle is

The Ansorg–Brügmann–Tichy single-domain pseudospectral solver for the puncture
equation — Phys. Rev. D **70**, 064011 — ported to C by Z. Etienne as
`nrpy.infrastructures.BHaH.general_relativity.TwoPunctures`, compiled against
GSL. `src/main.c` fills `ID_persist_struct` directly and calls `TP_solve` plus
`PunctIntPolAtArbitPosition`, so NRPy's `commondata` / NRPyPN / grid machinery is
not needed.

## The boundary this preserves

**The package never imports anything here.** `validation/twopunctures.py` shells
out to the compiled binary over a text protocol — argv in, `SUMMARY`/`POINT`
lines out — which is why the installed distribution stays `jax`/`numpy`/`scipy`/
`matplotlib` only and needs neither `nrpy` nor a C toolchain. If the binary is
absent, `validation.twopunctures.available()` returns `False` and the
oracle-dependent tests skip instead of failing.

## Interface

```
tp_solve b mA mB P nA nB nphi [Newton_tol] [Newton_maxit] [SA SB]
         [Pp0 Pp1 Pp2 Pm0 Pm1 Pm2 Sp0 Sp1 Sp2 Sm0 Sm1 Sm2]
```

Cartesian query points `x y z` arrive one per line on stdin, in TwoPunctures'
native frame (`m+` at `(+b,0,0)`, `m-` at `(-b,0,0)`). Numbers go to stdout;
TwoPunctures' own progress chatter goes to stderr. `validation/conventions.py`
holds the frame map between that convention and this package's.
